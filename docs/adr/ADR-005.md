# ADR-005 : Notifications Multi-Canal

## Statut
Adopté

## Contexte
La plateforme doit notifier les employés, RH et managers via différents canaux (email, Slack, in-app).

## Décision
- **Pattern** : Strategy Pattern pour l'envoi multi-canal
- **Canaux v1** : Email (SMTP), Slack (webhook), In-app (base de données)
- **Interface** : `NotificationChannel` avec méthode `send(recipient, subject, body)`
- **Template** : chaque notification est construite à partir d'un template défini dans `src/prompts/`
- **Historique** : toutes les notifications sont persistées dans la table `notifications`
- **Planification** : via le workflow `NotificationCycle` pour les rappels et échéances
- **Abstraction** : une couche `NotificationService` dans `application/use-cases/` orchestre le routage vers le bon canal selon les préférences du destinataire

## Conséquences
Positives :
- Flexibilité : ajouter un canal (SMS, WhatsApp) ne nécessite qu'une nouvelle implémentation de l'interface
- Traçabilité : historique complet des notifications envoyées

Négatives :
- Complexité accrue par rapport à un envoi email direct
- Gestion des échecs : stratégie de retry à implémenter
