# ADR-003 : Agents, Outils et Workflows Mastra

## Statut
Adopté

## Contexte
Mastra propose une API moderne pour définir des agents, des outils et des workflows. Nous devons standardiser leur utilisation.

## Décision
- **Agents** : modèle LLM passé comme chaîne `provider/model` (ex. `openai/gpt-4o`). Chaque agent a un `name`, `instructions` (prompt système) et une liste d'`tools`.
- **Outils** : obligatoirement via `createTool()` depuis `@mastra/core/tools` avec `id`, `description`, `inputSchema` (Zod), et `execute(context, data)`. Le premier paramètre `context` reçoit `requestContext`, `tracingContext`, `abortSignal`.
- **Workflows** : orchestrés via `@mastra/core/workflows`. Un workflow est un graphe d'étapes avec déclenchement conditionnel.
- **Agents** (3) :
  1. `OnboardingOrchestrator` : orchestre le parcours complet
  2. `QuestionnaireEngine` : génère et valide les questionnaires
  3. `NotificationAgent` : gère les notifications multi-canal
- **Workflows** (4) :
  1. `EmployeeOnboarding` : parcours complet d'intégration
  2. `QuestionnaireCycle` : cycle de vie des questionnaires
  3. `DocumentGeneration` : génération de documents PDF/texte
  4. `NotificationCycle` : envoi et suivi des notifications

## Conséquences
Positives :
- API Mastra standardisée et à jour
- Séparation claire entre agents, outils et workflows

Négatives :
- Nécessite de suivre les évolutions de l'API Mastra
