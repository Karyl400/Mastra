# ADR-004 : Schéma de Base de Données

## Statut
Adopté

## Contexte
La plateforme doit persister les employés, questionnaires, documents, notifications et progression d'onboarding.

## Décision
- **Moteur** : SQLite via Drizzle ORM (léger, zéro configuration, idéal pour MVP).
- **Tables principales** :
  - `employees` : informations employé
  - `tasks` : tâches d'onboarding
  - `questionnaires` : modèles de questionnaires
  - `questionnaire_responses` : réponses aux questionnaires
  - `documents` : documents générés
  - `notifications` : notifications envoyées/planifiées
  - `onboarding_progress` : progression globale par employé
  - `onboarding_steps` : étapes individuelles complétées
- **Clé primaire** : UUID v4 généré côté application
- **Timestamps** : `created_at`, `updated_at` sur chaque table
- **Soft delete** : champ `deleted_at` nullable pour les entités critiques

## Conséquences
Positives :
- SQLite : pas de serveur à gérer, backup simple (un fichier)
- Drizzle : types TypeScript stricts, migrations automatiques
- Schéma suffisant pour v1, extensible pour v2

Négatives :
- SQLite ne supporte pas les connexions concurrentes (limitation pour scaling horizontal)
- Migration vers Postgres nécessaire si le volume dépasse quelques Go
